# 🧩 RAG 헤딩 기반 청킹 및 서비스 안내 카테고리 설계

- 작성일: 2026-07-26
- 상태: 사용자 승인 설계

## 🎯 목표

모든 `data/documents` Markdown 문서에 동일한 헤딩 인지 청킹 전략을 적용해, 문서 구조를 보존하면서 검색 단위를 의미 있게 만든다. 서비스 이용 안내와 정책 안내는 `guide` 카테고리로 통합하고, 루틴 문서는 `routine` 카테고리로 유지한다.

## 🧱 청킹 규칙

### 1. `##` 헤딩이 있는 문서

- `##` 하나를 기본 청크 경계로 사용한다.
- `#`은 상위 문맥을 위한 제목이며 독립 청크 경계로 사용하지 않는다.
- 임베딩 텍스트에는 아래 브레드크럼을 앞에 붙인다.

```text
{front matter title} > {직전 H1} > {H2}

{H2 본문}
```

- `H2` 본문이 500자를 초과하면 빈 줄 단위로 추가 분할한다.
- 추가 분할된 모든 청크에도 같은 브레드크럼을 붙인다.
- 청크 간 overlap은 `0`이다.

### 2. `##` 헤딩이 없는 문서

- 기존 빈 줄 기준 문단 청킹을 폴백으로 사용한다.
- 문단이 500자를 초과할 때만 문단 내부를 추가 분할한다.
- 짧은 완결 문단은 다른 문단과 강제로 병합하지 않는다.
- 브레드크럼에는 front matter의 `title`만 사용한다.

## 🗂️ 카테고리 규칙

| 문서 성격 | metadata `category` | 검색 경로 |
| --- | --- | --- |
| 운동 루틴 및 운동 방법 | `routine` | 회원·트레이너 루틴 추천 |
| 결제, 환불, 구독, 예약, 화면 이용 방법 | `guide` | 챗봇 서비스 안내 |

- `data/documents/policy/`의 물리 경로는 유지한다.
- 정책 성격의 문서도 metadata `category: guide`를 사용한다.
- `짐짝_정책문서.md`도 metadata `category: guide`로 변경한다.
- 서비스 안내 라우트는 `guide`로 1차 필터링 후 벡터 검색한다.

## 🔎 검색 규칙

- 루틴 추천: `category="routine"`, `top_k=3`
- 서비스·정책·이용 안내: `category="guide"`, `top_k=3`
- `top_k`는 RAG 평가 결과가 기준 미달일 때만 5로 확대한다.
- `keywords`는 기존과 같이 사용자에게 노출하지 않는 검색 힌트로만 사용한다.

## ♻️ 인덱스 갱신

- 청킹 설정 식별자를 `paragraph-v1`에서 `markdown-heading-v1`로 변경한다.
- 문서 해시에 청킹 설정 식별자가 포함되어 있으므로, 기존 문서는 자동으로 갱신 대상이 된다.
- 기존 collection의 각 문서 chunk ID를 삭제한 후 새 청크를 삽입한다.
- 삭제된 문서의 stale chunk 정리는 이번 변경 범위에 포함하지 않는다.

## 🧪 검증 기준

- H2 청킹: H1은 문맥에 포함되지만 독립 청크를 만들지 않는다.
- 폴백 청킹: H2가 없는 기존 정책·루틴 문서가 정상 처리된다.
- 길이 제한: 생성 청크 본문은 500자 이하가 된다.
- 브레드크럼: H2 청크마다 title, H1, H2가 포함된다.
- 카테고리: 서비스 안내 검색은 `guide`, 루틴 검색은 `routine` 필터를 사용한다.
- 기존 `pt_recommendation` 문서 2개에 `id`, `source`를 보완해 전체 인덱싱에서 실패 문서가 없도록 한다.
- RAG 평가셋의 Recall@3 기준을 다시 실행해 회귀가 없는지 확인한다.

## 📌 범위 제외

- PDF 직접 인덱싱 지원
- 문서 삭제 시 stale chunk 자동 삭제
- `top_k=5` 기본 전환
- Gemini Embedding 모델 및 벡터 차원 변경
