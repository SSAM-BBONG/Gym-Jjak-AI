# 🧠 RAG 우선 · Gemini 일반 지식 보완 정책

- 작성일: 2026-07-27
- 상태: 구현·검증 완료
- 적용 도메인: 회원 루틴 추천, 트레이너 담당 회원 루틴 분석

## 🎯 리팩터링 배경

Gym-Jjak의 RAG 문서는 서비스 정책과 주요 운동 루틴의 신뢰 가능한 근거를 제공한다. 하지만 내부 문서만으로는 회원의 운동 환경, 이용 가능한 기구, 목표, 대체 운동, 세부 분할 방식처럼 다양한 요청을 모두 포괄하기 어렵다.

RAG 검색 결과가 없다는 이유만으로 운동 관련 루틴 추천을 거절하면 챗봇의 개인화 추천 가치가 낮아진다. 반대로 내부 문서 근거가 없는 내용을 내부 자료의 출처처럼 제시하면 답변의 신뢰성과 출처 정책이 훼손된다.

## ✅ 결정

회원·트레이너 루틴 추천은 아래 우선순위로 근거를 사용한다.

1. 검색된 `routine` RAG 문서
2. 회원의 실제 운동 기록과 인바디 기록
3. 온보딩 정보
4. Gemini의 일반 운동 지식

RAG 결과가 비어 있거나 요청을 충분히 다루지 못해도, 운동 관련 요청은 Gemini 일반 지식과 개인 데이터를 조합해 신중하게 루틴을 생성한다. 일반 지식으로 보완한 내용은 자연스러운 답변 안에 포함하며, 별도 라벨을 표시하지 않는다.

## 🔒 안전·출처 원칙

- 서버가 검색한 RAG 문서만 응답의 `sources`로 반환한다.
- Gemini 일반 지식으로 제안한 운동·세트·반복 수·대체 운동을 내부 문서 출처처럼 표기하지 않는다.
- 흉통, 실신, 호흡곤란 등 고위험 의료 신호가 있으면 RAG 결과와 무관하게 루틴 생성을 차단하고 진료를 권유한다.
- 일반 근육통은 제한적 안내와 전문가 상담 권고를 포함할 수 있다.
- 웹 검색, 외부 링크 수집, 별도 검색 API는 이 정책의 범위에 포함하지 않는다.

## 🏗️ 현재 구현과 보강 범위

현재 `app/routine/prompts.py`는 RAG 문서가 없을 때 `회원 기록과 일반 지식만으로 신중하게 답하세요`라는 문맥을 LLM에 전달한다. 또한 근거 우선순위에 Gemini 일반 지식이 마지막 단계로 정의되어 있다.

이번 보강에서는 다음을 명시적으로 고정한다.

- RAG 문서가 없거나 부족하다는 이유만으로 운동 관련 루틴 요청을 거절하지 않는다.
- Gemini 일반 지식은 RAG·개인 데이터 뒤에만 사용한다.
- 루틴 관련 일반 지식 보완은 출처 배열에 임의의 문서를 추가하지 않는다.
- 기존 의료 안전 차단 규칙은 변경하지 않는다.

## 🧪 검증 기준

| 시나리오 | 기대 결과 |
| --- | --- |
| `routine` 검색 결과가 0건인 일반 운동 루틴 요청 | LLM 호출까지 진행하고 루틴 결과를 생성 |
| 0건 검색 프롬프트 | RAG 부재와 일반 지식 보완 원칙을 포함 |
| RAG 문서가 있는 요청 | 검색 문서가 최우선 근거로 프롬프트에 포함 |
| 흉통·실신·호흡곤란이 포함된 요청 | LLM 호출 없이 `BLOCKED` 결과 반환 |
| 일반 지식으로 보완된 결과 | 서버가 검색한 RAG 문서만 `sources`에 포함 |

## 📸 증빙 캡처 계획

캡처에는 다음 두 정보를 같은 화면 또는 연속된 화면으로 남긴다.

1. `routine` 검색 결과가 0건인 테스트 조건
2. 개인 데이터와 Gemini 일반 지식으로 생성된 루틴 응답

이 증빙은 내부 문서가 없는 상황에서도 운동 관련 요청을 불필요하게 거절하지 않고, 안전·출처 원칙을 유지한다는 근거로 사용한다. 고위험 의료 요청 차단 화면은 별도 안전 정책 증빙으로 보관한다.

### 수동 확인 요청

`집에 운동기구가 없는 주 3회 초보자 전신 루틴 추천해주세요`

`routine` 검색 결과가 0건인 테스트 환경에서 루틴 응답을 생성하고, 응답 출처에는 위의 일반 지식 출처가 추가되지 않는지 확인한다. 흉통·실신·호흡곤란을 포함한 요청은 기존 시나리오와 별개로 차단되어야 한다.
